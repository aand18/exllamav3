**Hard rules for every task**

- The watcher is mandatory: no measurement, build or boot runs without a `WATCH` line in its
  report. Floor breach (`breach=1`, 200 MB free VRAM / 2048 MB free RAM) voids the run; do not
  reuse its numbers. A breach during a ladder step is a result ("this setting does not fit").
- One owner of the box: nothing else runs while a pass runs (`run_pass.ps1` refuses to start if a
  pass or server is alive). Ask the operator before the first GPU task of a session.
- No host installs or reconfiguration beyond installing the wheels built in Tasks 2/5 (and
  restoring the 1.5.4 wheel on rollback).
- Advise-only list, permanently: large pages / `SeLockMemoryPrivilege` (no privilege on this box),
  the WDDM memop handshake (measured 8–11% slower on 1.4.9), `EXL3_MOE_ZERO_COPY` (gone), KVaRN
  (operator decision), `EXL3_MOE_BLOCKING_SYNC` (~4% slower with MTP host syncs).
- Long runs go through the shell tool's background mode; never poll a background run.

## Measurement conventions

- **Screen at 131072, confirm at 262144.** A screening pass is ~10 min, a confirmation pass
  ~20–25 min. A decision is 4 passes (ABBA) unless stated otherwise.
- **ABBA on every comparison:** reference, variant, variant, reference. A ratio is only valid
  against a reference measured in that same session (boot-to-boot drift is real on this box;
  cross-process absolute numbers are not comparable — Engram #110).
- **Acceptance:** the median of the two per-band ratios must exceed the band's own spread
  measured in Task 3. No claim below the spread; no claim from absolute numbers across sessions.
- A difference inside the spread is **no difference**; record it and move on. A measured negative
  is a result.
- **Metrics:** pp = the `Length` bands of `perf.py`; tg = the `Context` rows at `S=1`. The
  `S=2..4` rows are the cost of a verification step, not an acceptance rate. Real MTP throughput
  and acceptance are measured in Task 9 with `eval/spec_decode.py`.
- Every pass records min-free VRAM, min-free RAM and peak process RAM (`FLOORS` block).

## The harness (committed in `bench/windows/` of this branch)

Everything runs through the scripts in `bench/windows/` — never write a new benchmark script:
add a regime to `run_pass.ps1`.

| Script | Purpose |
|---|---|
| `watch.ps1` | samples VRAM/RAM every 1 s, writes `results/watch-<tag>.csv`, kills the process tree and writes `results/BREACH-<tag>.txt` when 200 MB VRAM / 2048 MB RAM free is crossed |
| `run_pass.ps1` | one `perf.py` pass in a named regime, under the watcher, parsed into `results/{passes,pp,tg}.csv`, prints the `PASS/FLOORS/PP/TG_S1` block |
| `run_build.ps1` | one wheel build, under the watcher, records the wheel in `results/builds.csv` |
| `deploy.sh` | copies the three scripts plus `eval/perf.py` to the deploy directory |

Invocation from the WSL shell (note the `-Root` for v165):

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass -File \
  "C:\Users\yoho\Downloads\tabbyAPI\_agent\v165\run_pass.ps1" \
  -Tag <tag> -MaxLength 131072 [-Env "K=V,K=V"] [-Unset "K,K"] \
  [-Threads 16] [-Split 360] [-Extra "-cq 4,4"] [-NoSpecDec] [-Root "C:\Users\yoho\Downloads\tabbyAPI\_agent\v165"]
```

- `-Env` overrides the regime's environment; `-Unset` removes inherited variables.
- `-Threads` / `-Split` replace the regime's `-mct` / `-mcs`; both are recorded in `passes.csv`.
- `-Extra` appends raw `perf.py` flags. The exact args of every pass land in `passes.csv`.

`perf.py` in the deploy directory is a verbatim copy of `eval/perf.py` from this tree. It is
**byte-identical between v1.6.4 and v1.6.5** (verified 2026-10-29, empty diff), sha256
`246e721a62d7c5238de4b7296adb0b26cd9f42a734b9f648436b35b9b6a29e04`; it imports the **installed**
engine. `run_pass.ps1` refuses to run unless `exllamav3.__file__` is the installed venv copy.

## Parameter inventory — every v1.6.4 → v1.6.5 change that touches this box

Verified 2026-10-29 against `git log v1.6.4..v1.6.5` (44 commits) and the `doc/env_vars.md` diff.

### New knobs

| Knob | Kind | Default | Applies here? | Task |
|---|---|---|---|---|
| `EXL3_NO_BATCH_READBACK` | env | `0` (batched readback ON) | yes — one pinned-buffer readback per spec window instead of one per position; upstream measured +4–5% decode on a 27B MTP deployment on an RTX 4090 | **T9 (A/B the default)** |
| `EXL3_QC_STAGING_PAGES` | env | `256` (pages = 64k tokens) | yes — caps the fp16 prefill staging scratch; at 262k ctx the window is staged in slices. Interacts with quantized cache + pp | **T8** |
| `-sdh` / `--sparse_draft_head N` | CLI (perf.py/spec_decode.py via `model_init.add_args`) | `0` | yes — dynamic sparse LM head (N vocab columns) for MTP drafting; works with qwen4exp MTP (it borrows the trunk `lm_head` via `lm_head_argmax`, layer-split mode only, which is this box). Supersedes the hot-vocab feature that was merged and then removed within 1.6.5 | **T9** |
| `draft_max_rows` | Generator kwarg, no CLI | `0` (off) | no at bsz 1 — the ceiling only trims the window when `bsz*(1+draft)` exceeds it; record N/A unless the server runs concurrent streams | T9 (record N/A) |
| `prefill_cooldown=None` | Generator kwarg | — | caller-side only, no tuning surface | — |

### Removed / absent (do not look for them)

- MTP hot-vocab (`--mtp_hot_blocks`, `EXL3_MTP_HOT_BLOCKS`, …): merged in 1.6.5 then **superseded
  by the sparse draft head**; the files are not in the v1.6.5 tree. `-sdh` is its replacement.
- `EXL3_MOE_ZERO_COPY`: gone since 1.6.4.

### Defaults/behavior changed with no knob (already active once 1.6.5 is installed)

- Batched speculative-window readback ON by default (the A/B above).
- Sliced prefill staging scratch + 8-warp tiles (supersedes PR #517) — pp at long context.
- GDN b/a GEMV computes up to 16 token rows in one pass — qwen4_exp GDN prefill.
- A block's final residual add folded into the next block's input RMSNorm.
- CPU-MoE model-load bottleneck fixes + deferred loading kept when a saved expert profile is
  applied — faster load.
- Tokenizer chunking fix (#564) — prompt caching no longer silently fails on double-CRLF tokens.
- AVX2 / AVX-512-BW paired CPU-MoE kernels — commit says "measured unhelpful on VNNI/VBMI";
  the 7950X3D has VNNI, so expect neutral. No task; note it if load times move.

### Not applicable to this box

Shared-KV attention + Gemma4Assistant, Nemotron vision tensors, convert.py Hessian splitting,
QBench, `EXL3_FA75` (sm_75), Linux-only knobs.

DFlash2 is **not** in that list: the operator will test the DFlash2 drafter (Task 9b), so the
two 1.6.5 DFlash commits apply — `1a94d7a7` (budget the concatenated tap-layer hidden states at
load; large during prefill) and `1407bceb` (PR #546 fix applied to DFlash2).

### Doc fix

`EXL3_EXPANDABLE_SEGMENTS`: opt out with `0` (the 1.6.4 doc said `1` — doc bug, behavior

### Task 8: Cache mode, staging pages, recurrent checkpoints (GPU, ~10 passes)

The operator allows a quantized cache at 262k; the new `EXL3_QC_STAGING_PAGES` knob is what makes
long-context prefill with a quantized cache cheap in VRAM.

- [ ] **Step 1: Cache modes** at 131k against FP16: `-Extra "-cq Q8"`, `-Extra "-cq 4,4"`,
  `-Extra "-cq 2,2"`.
- [ ] **Step 2: Re-ladder the split** for the winning quantized mode at 262k — a quantized cache
  frees VRAM for more GPU experts, which is the point.
- [ ] **Step 3: `EXL3_QC_STAGING_PAGES`** at 262k with the quantized winner: `256` (default) vs
  `512` vs `1024` vs `64`, ABBA-style pairs, pp from the long `Length` bands, min-free VRAM
