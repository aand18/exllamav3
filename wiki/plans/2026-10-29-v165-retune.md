## Measurement conventions

- **Screen at 131072, confirm at 262144.** A screening pass is ~10 min, a confirmation pass
  ~20–25 min plus load (the 3.68 model loads noticeably longer than the old 2.05bpw). A decision
  is 4 passes (ABBA) unless stated otherwise.
- **ABBA on every comparison:** reference, variant, variant, reference. A ratio is only valid
  against a reference measured in that same session (boot-to-boot drift is real on this box;
  cross-process absolute numbers are not comparable — Engram #110).
- **Acceptance:** the median of the two per-band ratios must exceed the band's own spread
  measured in Task 4. No claim below the spread; no claim from absolute numbers across sessions.
- A difference inside the spread is **no difference**; record it and move on. A measured negative
  is a result.
- **Metrics:** pp = the `Length` bands of `perf.py`; tg = the `Context` rows at `S=1`. The
  `S=2..4` rows are the cost of a verification step, not an acceptance rate. Real drafting
  throughput and acceptance are measured with `eval/spec_decode.py` (Tasks 6–7).
- **After Task 7 freezes `DRAFT_WINNER`, every later tg measurement runs with that drafter on**
  (spec_decode arms) or with `-sd` verification rows comparable to it (perf.py arms). Record the
  drafter on every row.
- Every pass records min-free VRAM, min-free RAM and peak process RAM (`FLOORS` block).

### Fit on this box (measured 2026-10-29, T2/T4)

The 3.68bpw model at >=131072 with the Q2 cache sits on a knife edge in **both** resources, and
the two pull opposite ways:

| `-mcs` | CPU arena | result at full length |
|---|---|---|
| 372 | ~40 GB | **VRAM OoM during load** (layer 45, short by ~1 GiB) |
| 392 | ~42 GB | loads; killed at the 65536 prefill band with 23 MB VRAM free |
| 400 | 43.02 GB | host RAM: the engine's guard aborts the load transient by ~50 MB; steady state is fine (~5 GB free) |
| 448 | ~49 GB | physically oversubscribes 63.6 GB (guard skipped ran free RAM to 21 MB) |

- **The floors are the operator's, set 2026-10-29: watcher 100 MB free VRAM / 1200 MB free sys
  RAM** (previously 200/2048). They are now the harness defaults in both `run_pass.ps1` and
  `run_build.ps1`. With them plus guard 0, **split 400 runs a full 131072 pass clean** (`probe400`:
  PP 1701 t/s @4096, 1624 @131072; TG 43-48 t/s; min free VRAM 3207 MB, min RAM 3491 MB) - both
  resources comfortable, so the earlier kills were the two thresholds, not the model. The load transient dips ~2 GB deeper for `max_length >= 131072` than it does at
  4096 (min free RAM 5392 -> 2019 at the same split; `max_length` is not consumed by the loader,
  so the sizing difference is loader-internal), which is what killed every full-length attempt
  under the old floors.
- The engine guard is a separate tripwire the watcher's floors cannot help: with the regime's
  `EXL3_HOST_MEM_RESERVE_MB=1024` it aborts the last ~1.5 GB of arena chunks when the transient
  sits at ~2.0 GB available. Full-length passes therefore carry `=0` (the watcher holds the
  1200 MB margin; a guard double-charging the same margin aborts loads the floor would have
  survived). Cost if wrong: a failed load is recorded as a failure, not a machine risk.
- **Spec decode (`-sd`) costs ~1.1 GB of VRAM** (a second draft cache sized like the main one):
  drafting arms screen at 131072 (the plan's own screening length); Arm A is the no-drafting
  reference, and every later tg comparison uses a reference measured in the same drafting state.
- The arena lives in the engine's CPU-MoE **worker** process, so the watcher's
  `peak_proc_ws_mb` (the `perf.py` process) does not show it: read free RAM, not process RAM.
- Q2 cache, measured without a model load (`cachesize.py`): KV 1.875 GiB + GDN states 0.218 GiB
  = **2.093 GiB at 262144 tokens / 2 slots** - so the conclusive fit constraint is host RAM (the
  pinned arena), not KV.

## The harness (committed in `bench/windows/` of this branch)

| Script | Purpose |

### Defaults/behavior changed with no knob (already active once 1.6.5 is installed)

- Batched speculative-window readback ON by default (the A/B above).
- Sliced prefill staging scratch + 8-warp tiles (supersedes PR #517) — pp at long context.

- A block's final residual add folded into the next block's input RMSNorm.
- CPU-MoE model-load bottleneck fixes + deferred loading kept when a saved expert profile is
  applied — faster load (matters more now: the production model is 62 GB).
- Tokenizer chunking fix (#564) — prompt caching no longer silently fails on double-CRLF tokens.
- AVX2 / AVX-512-BW paired CPU-MoE kernels — commit says "measured unhelpful on VNNI/VBMI";

- DFlash load fixes (`1a94d7a7` tap-layer hidden-state budgeting, `1407bceb` PR #546) — live
  only once a DFlash drafter is loaded (Task 7).
